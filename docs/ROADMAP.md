# 迭代路线

## v0.1：可测试的通用执行骨架

- 已实现：任意维度关节布局、同步/异步调度、时间戳对齐、三种合并、线性/单调三次插值、独立控制时钟、速度限制、故障传播、模拟器、执行后报告。
- 已提供：模型 callback + codec、设备 callback、调度扩展示例、模拟配置、自动测试和 editable draw.io。
- 尚未验收：新框架的实机表现、硬件驱动插件、碰撞与力控。

## 下一阶段：设备与原 inference 对照

1. 独立 Piper 插件：底层消息新鲜度、左右 CAN 映射、模式所有权、保持语义。
2. 原 worker 与新 runtime 的 A/B：相同输入 chunk，比较切换跳变、实际下发周期、设备反馈延迟及抓取表现。
3. 第二种构型设备验收，例如 7 轴单臂或含升降轴构型；不能仅以维度测试声称跨机器人部署完成。

## 调度与轨迹

- 模型专用 RTC / future-conditioned 适配器，保存 model-space 前缀和 request/output lineage。
- 不改变旧 episode 的异步取消、进程隔离模型客户端和动态延迟估计。
- 速度/加速度/jerk 受限重定时；对限速造成的时间漂移做显式处理。
- 任意时间戳粗轨迹编译器，自动补终点保持段及反馈到位判断。

## 运行与可视化

- 实机端 timing / feedback trace、跟踪误差阈值、总线看门狗集成。
- 独立进程 telemetry sink / 本地 Web 查看器；任何慢可视化消费者都不能阻塞控制。
- 对需要硬实时的设备增加 C++/实时控制后端，保留同一数据及停止契约。

每一步必须给出相应验收数据；架构预留接口不作为算法已经实现或实验成功的证据。
